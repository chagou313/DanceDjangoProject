# 响应式导航布局修复设计

## 目标

修复首页在桌面和中等宽度窗口中导航文字逐字换行、导航栏异常增高、首页主视觉被遮挡的问题；同时为手机端提供可展开、可操作的完整导航。保留现有黑金视觉风格、页面路由和登录逻辑。

## 问题根因

- 导航容器同时承载品牌、六个主要入口、用户名和退出按钮，现有间距与字号在可用宽度不足时超过一行。
- 品牌、导航链接和认证按钮允许收缩及中文断行，因而被压成多行。
- 响应式断点仅设置在 `768px`，中等宽度没有专门布局。
- 导航栏使用固定定位，但正文采用固定的顶部留白；导航变高后会覆盖首页主视觉内容。
- 手机端直接隐藏主要导航，没有替代入口。

## 方案

### 桌面与中等宽度

1. 品牌、主要导航项、用户名和认证按钮保持单行，不允许逐字断行。
2. 宽屏保持当前完整导航；在较窄桌面宽度下降低导航间距、字号和按钮内边距。
3. 当完整导航无法舒适容纳时，提前切换为折叠菜单，避免依赖浏览器压缩元素。
4. 为固定导航设置稳定的布局高度，并让正文顶部留白引用同一 CSS 变量，防止首页被覆盖。

### 手机端

1. 显示品牌和汉堡菜单按钮。
2. 点击按钮展开或收起纵向菜单；主入口、已登录用户信息及退出入口都可访问。
3. 菜单按钮具有 `aria-expanded`、`aria-controls` 和清晰标签，支持键盘操作。
4. 点击菜单链接、点击菜单外部或按 `Escape` 后关闭菜单。

### 保持不变

- 不修改数据库、图片、模型、路由或后端业务逻辑。
- 不改变现有导航目标和登录状态判断。
- 不重做首页内容与配色，仅校正顶部占位和响应式尺寸。

## 验证方式

- 添加模板回归测试，确认折叠菜单按钮、导航容器标识、可访问性属性和控制脚本存在。
- 运行 Django 系统检查及相关自动测试。
- 在已登录状态下实际验证宽屏、中等屏幕和手机宽度：首页不被遮挡、导航不逐字换行、手机菜单可以开关、退出入口可见。

## 验收标准

- 宽屏导航保持一行，品牌、导航名称及“退出”不再逐字换行。
- 中等宽度不会出现异常增高的固定页头。
- 首页标题完整显示，不被导航栏覆盖。
- 手机端可以展开和关闭菜单，并访问全部主要页面及登录相关操作。
- 页面无明显横向溢出，现有下拉菜单在宽屏下继续工作。
