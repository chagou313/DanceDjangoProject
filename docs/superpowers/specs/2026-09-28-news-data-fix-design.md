# 新闻资讯空白修复设计

## 目标

修复“新闻资讯”列表为空的问题，同时保持现有舞蹈项目、传承人和用户数据不变。修复后，首次启动空新闻数据库时会自动生成一批基于现有非遗舞蹈项目资料的站内“项目导读”，新闻列表和详情页可正常访问。

## 已确认的根因

1. 页面读取 `news.News`，当前表中没有记录。
2. 现有 Excel 只有“项目情况概要”和“传承人”，没有新闻工作表。
3. 旧导入脚本的“相关资讯”分支只有读取语句，没有创建新闻记录。
4. 项目同时存在 `news.News` 和 `origin.News` 两套模型。立即删除旧模型会引入不必要的迁移风险。

## 方案比较

### 方案 A：只在后台手工添加新闻

改动最少，但换一份数据库后问题会再次出现，也不能解决导入脚本未完成的问题。

### 方案 B：只补 Excel 导入

适合后续真实新闻数据，但当前 Excel 没有新闻工作表，修复后页面仍然为空。

### 方案 C：统一当前读取路径，增加幂等初始化并补齐导入（采用）

继续让页面使用功能更完整的 `news.News`。新增幂等初始化命令，在新闻表为空时根据已有舞蹈项目的名称和简介生成站内“项目导读”。补齐 Excel 新闻导入入口，让以后新增“新闻资讯”或“相关资讯”工作表时可以导入真实内容。旧 `origin.News` 暂时保留，避免本次修复扩大为高风险数据库迁移。

## 数据与内容规则

- 初始化内容只使用本地已有的舞蹈项目名称、简介和地区信息。
- 标题明确采用“项目导读：项目名称”，不冒充新闻事件或外部媒体报道。
- 默认创建 12 条；项目少于 12 个时按实际数量创建。
- 使用稳定标识判断是否已经创建，重复执行不会产生重复新闻。
- 作者使用专门的站内系统账号；不会修改现有用户资料。
- 只有在 `news.News` 完全为空时，一键启动脚本才执行初始化。

## 组件改动

1. 新增 `news` 管理命令，负责幂等生成项目导读。
2. 调整一键启动脚本，在迁移完成后、启动服务前调用初始化命令。
3. 补齐 Excel 新闻导入逻辑，写入 `news.News`，并兼容“新闻资讯”和“相关资讯”两个工作表名。
4. 保持新闻列表、详情、点赞、收藏现有路由与模板不变。

## 错误处理

- 没有舞蹈项目时，初始化命令明确提示并安全退出。
- 缺少新闻必填列时，Excel 导入报告缺失列，不写入不完整记录。
- 找不到关联项目时，允许新闻不关联项目，但保留标题与正文。
- 单条无效数据不会覆盖或删除已有新闻。

## 测试与验收

1. 在空新闻表上执行初始化命令，生成预期数量的新闻。
2. 再执行一次，新闻数量保持不变。
3. `/news/` 返回 200，并展示已生成标题。
4. 任意新闻详情页返回 200。
5. 一键启动脚本在已有新闻时不重复写入。
6. Django 系统检查和项目测试通过。

## 明确不做

- 本次不删除 `origin.News`，不做破坏性数据库迁移。
- 不抓取互联网新闻，不虚构外部新闻来源或发布日期。
- 不覆盖现有项目、传承人或用户数据。
