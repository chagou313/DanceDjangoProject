# 舞蹈项目图片关联恢复设计

## 目标

恢复现有 356 条 `DanceProject` 记录的图片，使网站继续通过模型的 `images` 字段和 Django media 路径显示图片。不修改数据模型、页面模板或现有图片文件。

## 已确认事实

- SQLite 中共有 356 条舞蹈项目记录，所有 `images` 字段为空。
- `media/origin/20260407/` 中共有 365 张图片。
- 原 MySQL 数据库、旧 SQLite 数据和 Excel 均不再保存项目与图片的原始对应表。
- 用户确认采用确定性恢复：项目按主键升序，图片按文件创建/修改时间升序，再以文件名作为次级排序键，一一对应。

## 恢复规则

1. 读取 `DanceProject`，按 `id` 升序排序。
2. 读取 `media/origin/20260407/` 下的普通图片文件，按修改时间升序、文件名升序排序。
3. 前 356 张图片依次写入 356 条项目记录的 `images` 字段，保存为相对 media 路径，例如 `origin/20260407/pasted-image.png`。
4. 剩余 9 张图片保持原状，不删除、不移动，也不写入数据库。
5. 命令默认拒绝覆盖非空图片字段；只有显式传入覆盖选项时才允许覆盖。
6. 写入在一个数据库事务中完成；任何校验或写入失败都整体回滚。

## 数据保护

- 执行前复制当前 `db.sqlite3`，备份名包含执行日期和用途。
- 不修改用户已有的其他代码改动或媒体文件。
- 恢复命令支持预演模式，只输出项目数、图片数、计划写入数和剩余图片数，不修改数据库。

## 实现范围

- 新增一个 Django management command，负责扫描、校验、预演和写回图片路径。
- 新增针对排序、路径格式、数量不足、拒绝覆盖、事务写入和预演模式的自动测试。
- 不创建 MySQL 数据库，不切换当前 SQLite 配置。

## 验收标准

- 相关自动测试全部通过。
- 预演报告为：356 个项目、365 张图片、计划关联 356 条、剩余 9 张。
- 正式执行后，356 条项目的 `images` 字段均非空。
- 数据库引用的 356 个图片路径全部存在于磁盘。
- 首页、项目列表或项目详情页请求成功，生成的图片 URL 能由本地开发服务器访问。

## 限制

旧的精确映射已经丢失，因此按时间顺序恢复不能保证每张图片与原项目语义完全相同。本方案恢复原有字段关联机制和稳定的一对一关系，不声称还原历史上的逐条对应关系。
